# 实现说明（原理与设计取舍）

本文写给想看源码 / 想改的人。只想知道怎么用的话，看 [README](../README.md) 就够了。

## 1. 总体结构

```
desktop/kun-pet-desktop.ps1     单文件应用：WPF 渲染 + 状态机 + 素材加载 + 托盘 + 审批面板
desktop/kun-pet-pi-source.ps1   pi coding agent 源适配器（只读尾随 + 扩展快照，可单独自测）
desktop/kun-pet-wander.ps1      随机移动的纯函数（选点 / 步进 / 夹取 / 守卫，可单独自测）
desktop/kun-pet-update.ps1      更新的纯函数（版本比较 / 清单筛选 / 内容校验 / 原子替换+回滚）
desktop/version.json            版本号、发版说明、可更新文件清单（更新源里的同名文件）
desktop/tests/                  pi 源适配器 + 随机移动 + 更新的自测（不需要真的起桌宠）
plugin/index.js                 DSH 插件 host 半区：状态机、HTTP/文件双通道、审批应答
plugin/client.js                DSH 插件 client 半区：DSH 网页右下角那只小宠
pi-extension/kun-pet.ts         pi 扩展：把 pi 状态写成 JSON 快照（含「正在等你」）
tools/add-bom.ps1               给含中文的 .ps1 补 UTF-8 BOM（见下文「编码」一节）
install.ps1 / uninstall.ps1     安装 / 卸载
tools/autostart/                开机自启模板（纯 ASCII）
```

桌宠**不依赖插件也能跑**：拿不到任务状态时就停在待机动画。插件提供「工具名 + 审批」两类信息；任务进展默认读会话投影缓存。

### 编码：`.ps1` 必须带 UTF-8 BOM

Windows PowerShell 5.1 对**没有 BOM** 的 `.ps1` 按系统 ANSI 代码页（中文机器是 GBK）读取。
脚本里有中文时，轻则乱码，重则某些 GBK 双字节序列把后面的引号吞掉 ⇒ **直接语法错误**。
仓库里所有含非 ASCII 的脚本都带 BOM；`tools/add-bom.ps1` 用来在编辑后补回。
`tools/add-bom.ps1` 自己是**纯 ASCII 且不带 BOM**（这样它在任何代码页下都能跑起来执行修复）。

> 这条是**实测**结论：用 `powershell -File` 跑过一遍所有脚本，不带 BOM 时会报
> `Unexpected token '浼氳瘽...'` 之类的解析错误。`启动桌宠.vbs` 之所以不受影响，
> 是因为它自己用 `[IO.File]::ReadAllText(path, UTF8)` 读取后再交给 ScriptBlock。
>
> CI 里本来就有这条检查（`.github/workflows/checks.yml`），所以「含中文的 `.ps1` 必须带 BOM」
> 一直是本仓库的既定规则 —— 只是历史上这些文件并没有真的带 BOM，属于存量遗漏。

## 2. 状态从哪来（三级降级）

| 优先级 | 来源 | 能得到什么 |
|---|---|---|
| 1 | 插件 HTTP `/kun-pet/state` | 当前模式、正在执行的工具名、**待审批列表** |
| 2 | 会话投影缓存 `~/.dsh/storages/session_projcache/sessions/*.json` | 是否在跑、跑了几轮几步、**是否在等你回答**、当前任务内容、模型/工具耗时 |
| 3 | `~/.dsh/sessions` 文件写入时间 | 粗略活跃度（兜底） |

底部小字会显示当前实际生效的来源。

### 为什么优先读会话投影缓存

审批**不在**会话投影里，但「在跑 / 轮次 / 任务内容 / 是否在等你回答」都在，而且是**明文 JSON、始终可用**（不需要插件挂上、不需要知道端口）。所以桌宠的默认数据源是它，插件的 HTTP 端点作为**增强**（补「正在执行哪个工具」和审批）。

### 只跟随主会话

子代理（subagent）会话也有同样的缓存文件，而且干活时更新更频繁。桌宠通过
`record.rows.subagent.val.identity.mode` 是否存在来识别子代理并跳过，避免把子代理的状态显示成你的主任务。

### 多会话聚合

桌宠是**全局**的：扫描全部活跃主会话，逐会话跟踪「上一帧是否在跑」，聚合出全局模式与逐任务进展。
旧实现只取「最近写入的一个会话」，于是别的会话就算还在进展中也会被忽略（表现为「任务在跑却没有气泡」）。

### 一个容易踩的坑：问题藏在嵌套里

会话投影里，Agent 的提问挂在 `userQuestions.val.questions.active[]` 的**嵌套 `questions[]`** 里
（字段：`id / question / detail / header / options[{label,description}] / multiSelect / intent`）。
早期代码直接读条目本身的 `question`，于是永远只显示一句「Agent 正在等待你的回答」。

另一个坑：`active` 条目的 `state` 为 `continued` 时表示**已经答过、Agent 正在继续**，
只认 `state = open` 才是真的在等你。

### pi coding agent 作为并行数据源

`kun-pet-pi-source.ps1` 把 pi 也做成一个源，产出与上面**完全相同形状**的快照，
所以渲染/动画/提醒/多任务展示一行都没改。两条通道自动降级：

| 通道 | 位置 | 覆盖面 |
|---|---|---|
| 扩展快照 | `~/.pi/agent/kun-pet-state.json`（`pi-extension/kun-pet.ts` 每 5s 心跳重写） | 全部 + **「正在等你确认」** |
| 会话尾随 | `~/.pi/agent/sessions/<转义cwd>/<ts>_<id>.jsonl`（只读） | 在干活 / 收尾 / 出错 / 模型 / 轮次 |

**为什么「等待确认」必须靠扩展**：pi 的会话文件里没有任何「正在弹确认框」的记录，
唯一能表达的官方信号是 `ui_prompt_start` / `ui_prompt_end` 事件，它只在扩展上下文里可见。

#### 判定规则（只依赖 pi 的核心记录类型）

| 信号 | 结论 |
|---|---|
| 有 `toolCall` 没有配对的 `toolResult`（悬空） | 在干活（**不看 mtime**，最强信号） |
| 尾部 assistant 且 `stopReason='toolUse'` | 在干活 |
| 尾部是 user/toolResult 且文件 < 180s | 在干活 / 思考中 |
| 尾部 assistant 且 `stopReason='error'` 且 < 15s | 出错 |
| 配平 + 尾部 `stopReason='stop'` + 刚结束 | 任务结束（**逐会话下降沿**触发一次） |

**刻意不用 `custom/agent-summary` 判收尾**：那是**扩展**写的（`deepseek-cache` 之类），
纯净安装下不存在，只能当摘要加分项。核心信号是「配平 + mtime + stopReason」。

#### 三个必须处理的读取坑

1. **读头 ≠ 读尾**。会话头（`cwd`/`id`/`version`）在第一行，可能远在尾部窗口之外，
   所以 `Read-PiHeadText`（读文件开头 4KB）与 `Read-PiTailText`（读末尾 256KB）是
   两个函数。早期把两者合成一个「取最后 N 字节」的实现，导致所有 >4KB 的会话都被
   当成「不是 pi 会话」跳过 —— pi 支持静默失效。
2. **两个截断点**。尾部窗口首行可能是半行（丢弃）；末行可能正被写入、没有结尾换行
   （丢弃），否则会解析到半条 JSON。
3. **BOM**。`.NET Framework` 的 `Trim()` 不把 `U+FEFF` 当空白，不显式剥掉的话首行会以
   BOM 开头，`$t[0] -ne '{'` 会把 session 头整行丢掉。

另外：取文件长度只读元数据、不读内容（`Read-PiSlice` 在 `maxBytes -le 0` 时直接返回），
否则每次轮询都会把整个会话文件读进内存，正好废掉「只读尾部窗口」的意义。
实测本机最大的会话文件有 **2.4 MB**，这个优化不是纸面上的。

接入层单独测是有意的：模块自己测通了，不代表 `kun-pet-desktop.ps1` 里那段仲裁写对了。
集成测试把主脚本的仲裁分支**逐条重放**，包括「DSH 与 pi 同时在跑 → 并列显示」和
「pi 在等 → 优先于 DSH 在跑」。

写测试时踩到的坑（**已实测确认**，留作前车之鉴）：

- `test-pi-integration.ps1` 里的 `Check` 是 `Check <名称> <实际> <期望>` **三个**参数。
  少传第三个时 `$expected` 会默认成 `$null`，于是断言拿 `'True'` 去比 `<null>`，
  报出来的是「期望=`<null>` 实际=True」这种看着像被测代码坏了、其实是**测试自己**写错的失败。
  断言布尔值请用 `CheckTrue`（内部固定和 `'True'` 比）。
- （顺带纠正两个我原以为的坑，实测**不成立**，不要照抄到别处：
  `-match` 不匹配时返回的是布尔 `$False` 而不是 `$null`；
  `return ,$list` 与 `return $list` 在函数返回值上表现一致 ——
  外层数组会被 PowerShell 的管道再展开一层。）

#### 子代理排除（按目录层级，精确且零代价）

`pi-subagents` 的子女会话**不会**直接写进 `<sessions根>/<转义cwd>/*.jsonl`。读过它的源码
（`src/shared/artifacts.js` 的 `getArtifactsDir`）并本机实测确认，子会话产物落在：

| `artifactDir` | 位置 | 是否在 sessions 根下 |
|---|---|---|
| `session`（**默认**） | `<sessions根>/<转义cwd>/subagent-artifacts/…` | 是，但**深一层** |
| `project` | `<项目>/.pi/subagents/artifacts/…` | 否 |
| `temp` | 系统临时目录 | 否 |

因此**主会话的路径段数恒为 2**（根/转义cwd/文件），任何 ≥3 段的 `.jsonl` 都是子代理产物，
按段数过滤即可：既精确，又不影响正常会话。日志会写 `skipped nested session file`。

> ⚠️ **曾经走错的方向**：最初我用「同一 cwd 只保留一个会话」（按用户轮次排序）来防子代理。
> 这是**错的** —— 它把「同一项目目录下开了多个 pi 窗口」误判成子代理，导致**多开只显示一个任务**
> （用户实际报过这个问题）。多窗口是常见用法，绝不能被合并。

> ⚠️ 层级**也不能用 `Substring($root.Length)` 算**。那要求两边字符串长度严格对齐，
> 一旦路径被规范化过（8.3 短名长名混用、尾斜杠、符号链接）就会切错位置 ——
> 实测出现过相对路径变成 `'sions\proj\a.jsonl'`（多切了 6 个字符），
> 层级算成 3 → 该会话被判为子代理**静默跳过**，pi 支持整体失效且毫无报错。
> 现在用 `Get-PiLevelsBelowRoot()`：从目录**向上逐级比对**父目录的 `FullName`
> （`OrdinalIgnoreCase`），与字符串长度无关。

> 结论：pi 会话头里确实没有 `parentSessionId`（本机 39 个文件复核，命中 0），
> 但**不需要**靠它来判断 —— 目录层级已经能精确区分。

## 3. 更新模块

已安装的桌宠可以一键更新。更新源是 **GitHub raw 逐文件**：

```
https://raw.githubusercontent.com/ddldydd/kun-desktop-pet/main/desktop/<file>
```

**为什么不用 zip / git clone**：实测 `codeload.github.com`（zip 下载源）在本机**直连与代理都失败**，
而 `raw.githubusercontent.com` 稳定可达（HTTP 200）且能正确保留 UTF-8 BOM。
所以只能逐文件取（desktop/ 下几个脚本，约 260KB）。

### 安全设计（这是本模块的重点）

| 机制 | 为什么 |
|---|---|
| **先全部下载 + 校验，再替换** | 绝不出现「替换了一半、程序坏了」。任一文件失败 → 整体放弃，磁盘原封不动 |
| **替换前整份备份** | 备份到 `backup-v<版本>-<时间戳>/`，用户可手工回滚 |
| **失败自动回滚** | 替换途中异常 → 从备份恢复，并把备份路径写进错误信息 |
| **`File.Replace` 原子替换** | 不用「先 `Remove-Item` 再 `Move-Item`」——那中间有个窗口期目标文件不存在 |
| **内容校验** | `.ps1` 必须能被 Parser 解析；HTML/404 页被显式拒绝 |
| **白名单 + 纯文件名** | 更新清单来自网络（**不可信输入**）；只接受白名单内的纯文件名，挡路径穿越 |
| **不碰用户数据** | `kun-pet-settings.json` 与 `*.log` 不在白名单里，永远不被覆盖 |

### 三个实测踩到的坑（都会导致功能不可用）

1. **BOM 必须剥掉再解析**。
   仓库里所有 `.ps1` 都带 UTF-8 BOM（CI 强制），从网络取回并解码后字符串开头就是 `U+FEFF`，
   Parser 会报「表达式中存在意外的标记」。不剥的话**每一个真实文件都被误判为不合格**
   —— 更新功能整体失效。这个 bug 是「用真实 GitHub 文件跑一遍」才发现的，
   只用自己造的测试字符串永远发现不了（我的夹具当初就没带 BOM）。
2. **HTML 恰好是合法的 PowerShell 语法**。
   网络出错时服务器常返回 HTML 错误页，而 `<` 是重定向、`>` 是输出重定向，
   Parser **居然解析通过**。只靠 Parser 挡不住，必须显式识别 `<!DOCTYPE` / `<html` / 首行标签。
   不挡的话桌宠会装上一个网页，然后起不来。
3. **`File.Replace` 的第 3 个参数不能传 `$null`**。
   Windows PowerShell 5.1 下会抛 `The path is empty. (Parameter 'path')`。
   要给一个真实路径（用完即删）。

另外：**测试里注入「失败」的手段本身要先验证真能失败**。
我最初用「空目录占位」注入替换失败，结果对空目录居然替换成功了，
于是回滚测试**假通过**；改成非空目录才真正触发失败并验证了回滚。

### 版本号有两处，必须一致

`desktop/version.json`（更新源里那份，代表最新版）与脚本里的兜底值
`$Config.Version`（读不到 version.json 时用）。两者不一致会导致
「每次启动都提示有新版却永远装不上」或「明明有新版却说已是最新」。
CI 里加了一步专门校验两者相等。

---

### 提示走气泡，不走弹窗（实测结论）

「检查更新」的结果原本用 `MessageBox` 提示。实测发现**用户可能看不到**：

| 写法 | 是否 Topmost | 相对桌宠的 z 序 |
|---|---|---|
| WinForms `MessageBox`（不传 owner） | ❌ `topmost=False` | **在桌宠之下** |
| WinForms `MessageBox`（传 owner） | ❌ `topmost=False` | **在桌宠之下** |
| WPF `MessageBox`（传 WPF Window 作 owner） | ✅ `topmost=True` | 在桌宠之上 |

桌宠本身是 **Topmost** 窗口，所以前两种弹窗会落在它**下面**，可能被挡住；
而且弹窗会**抢焦点**，打断用户正在打的字。

所以：**结果提示一律走气泡**（贴在置顶的小宠上，一定看得见，且完全不打断操作），
只有**不可逆操作**（真的要替换程序文件）才弹窗确认，且用 WPF 那种（带 Topmost）。

气泡提示的优先级判断放在 `kun-pet-ui.ps1` 的 `Resolve-BubbleText`（纯函数，可自测）。
它**优先级最高**，必须盖过「等待介入」「进行中」这些常态文案 ——
否则任务正好在跑时点了菜单，气泡被进展占着，用户依然看不到回应。

运行时实测（真实点菜单 → 读窗口上气泡控件的实际文字）：
```
   66 ms  🔍 正在检查更新… / 当前版本 v2.2.0
 1719 ms  ✅ 已是最新版本 v2.2.0 / 无需更新
 9902 ms  我先去干活啦！           ← 8 秒后自动消失，回到常态
```

### 联网必须放后台，否则「即时反馈」根本画不出来

上面那条 `66 ms` 的即时反馈来之不易。最初这一步是**同步**下载的，结果实测发现：

- `animTimer` 是 `DispatcherTimer`，回调跑在 **UI 线程**上；
- 同步 HTTP 在 UI 线程里执行 → 网络不可达时要等 **~10 秒**才抛异常；
- 这 10 秒 UI 完全冻结，气泡**不重绘** —— 我特意加的「🔍 正在检查更新…」
  **一次都没显示出来**；
- 用户看到的是「小宠卡住不动，10 秒后突然报错」，
  恰恰就是我想避免的「点了没反应」。

改成后台 runspace（`[powershell]::Create()` + `BeginInvoke`）+ 一个
`DispatcherTimer` 轮询 `IsCompleted` 后，`BeginInvoke` 实测 **2 ms** 返回，
UI 全程可响应，提示立刻可见。**凡是联网/耗时的操作都不能直接放在 UI 事件里。**

## 4. 随机移动（到处跑）

小宠自己在桌面上溜达：随机挑目标 → 匀速走过去 → 到点随机歇 1~5 秒 → 再挑下一个。
默认**关**（宠物自己会动是有打扰性的，必须用户主动开）。

**几何计算全在 `kun-pet-wander.ps1`**（纯函数，不碰 WPF），所以能脱离桌宠自测：
`Get-WanderTarget`（选点）、`Get-WanderStep`（走一步）、`Get-WanderClamped`（夹回屏内）、
`Get-RandDouble`（区间随机）、`Test-WanderAllowed`（这一帧能不能动）。
驱动窗口的 `Update-Wander` 留在 `kun-pet-desktop.ps1`，因为它要访问 `$window`/`$state`。

几个刻意的取舍：

| 做法 | 原因 |
|---|---|
| 用**单位向量 × 速度** | 否则对角线方向会快 √2 倍，看起来像在窜 |
| 剩余距离 < 一步时**直接落在目标点** | 不这么做会在目标附近来回抖（永不「到达」） |
| 坐标取整 | 素材形态下亚像素位移会让像素贴图每帧重采样，就是那个「频闪」 |
| 每帧都**夹一次**工作区 | 气泡变长会把窗口顶出屏幕（实测出现过 `posTop = -7`），夹一下能顺便修正 |
| 到点后**随机歇 1~5 秒** | 一刻不停像无头苍蝇，歇一下更像「活物」 |
| `Test-WanderAllowed` 放进**模块** | 见下 |

### 为什么守卫函数要放进模块

「什么时候不许动」的判断（拖拽中 / 暂停 / 鼠标悬停 / 等你介入 / 审批面板在显示 /
坐标还是 NaN）如果内联在 `Update-Wander` 里，测试就只能**复制一份**判断逻辑去断言。
那份复制品会随着产品代码改动而失真，而测试照样全绿 —— 那种测试没有价值。

放进模块后，`test-wander-guards.ps1` 直接调用**产品代码里的那个函数**，
改了逻辑测试就会跟着失败。

另外三条护栏对应的是真实的可用性问题：
- **拖拽中不动**：程序改 `Left/Top` 会跟鼠标抢窗口，手感炸裂
- **暂停时不动**：暂停的语义是「冻结小宠」，这时还满屏跑就自相矛盾
- **等你介入时不动**：审批面板上有 ✓/✗ 按钮，宠物一边飘一边等你点，按钮会跑掉、可能点错

## 5. 频闪是怎么修的（v2 的两个根因）

现象：小宠每隔约 1 秒「消失一瞬」再出现。

**根因 1：素材每行末尾有空帧。**
petdex / Codex 的精灵图统一是 8 列，但每个动作真正有内容的帧数不同。实测：

| 形象 | idle | running-right | running-left | waving | jumping | failed | waiting | running | review |
|---|---|---|---|---|---|---|---|---|---|
| ikkun | 6 | 8 | 8 | 4 | 5 | 8 | 6 | 6 | 6 |
| haiyue-classic | 6 | 8 | 8 | 4 | 5 | 8 | 6 | 6 | 6 |

固定按 8 列循环时，走到空格子小宠就「不见了」。
现在**启动时逐行扫描素材**（`KunPet.SpriteScan.UsableCols`，读 BGRA 的 alpha 通道，隔行隔列采样），
只在该行真正有内容的列之间循环，并把 `frames/row: 6,8,8,4,5,8,6,6,6` 写进日志。

**根因 2：逐帧亚像素缩放/位移。**
整只小宠每帧按 ±2% 重新缩放并做小数位移，像素贴图每帧重新采样，边缘来回抖。
现在**素材形态下缩放固定、位移取整**（提醒时的脉冲改成整像素弹跳），每帧栅格完全一致 ⇒ 画面是稳的
（连续帧可以一模一样）。内置矢量形象是纯路径、缩放不重采样，所以保留原来的呼吸 / 脉冲效果。

顺带修掉的三个问题：

- **气泡一窄小宠被裁**：窗口是 `SizeToContent`，气泡宽度会改变窗口宽度，而贴图比容器大、不参与布局，
  于是气泡窄时小宠左右被裁。现在容器尺寸跟着素材格走，整张贴图都计入布局。
- **气泡换行时小宠上下跳**：窗口从左上角扩展，气泡多一行小宠就下移一截。现在尺寸变化时钉住
  「**底边 + 水平中心**」：气泡向上生长，小宠待在原地；存盘也一并存窗口尺寸，重启后按底边+中心还原（并夹在工作区内）。
- **启动时处于暂停会显示 `...`**：现在暂停（菜单切换或带 `paused` 启动）也会按当前状态渲染一次气泡与底部提示。

自查工具：

- `docs/tools/check-sheet-frames.py` —— 打印每个形象每行的有效帧数（找出空帧）
- 想验「画面不闪」：连续截图比对小宠区域像素数是否稳定

## 6. 暂停的语义

菜单里的「暂停」**只冻结小宠本身**：不推进动画帧、不浮动 / 缩放、点击不再挥手出声。
**任务气泡、进度、底部提示、提醒全部照常更新**——暂停动画也不会漏掉任务进展。

实现上：500 ms 轮询照常跑、状态该切就切；动画定时器在暂停时仍然刷新气泡文字 / 进度 / 等待提示，
只是不重画小宠；提示音、托盘通知、置顶抢焦点同样有效。

## 7. 审批通道（插件的核心）

### 两条通道

| 通道 | 位置 | 能力 |
|---|---|---|
| HTTP | `/kun-pet/state`、`/kun-pet/approval` | 读状态 + **在桌宠上直接 ✓同意 / ✗拒绝** |
| 文件 | `~/.dsh/kun-pet-state.json`（内容与 HTTP 响应体一致） | 读状态（气泡照常提示，决策要回 Harness 点） |

桌宠优先 HTTP，失败自动退回文件。只有文件通道时，气泡会提示「切回 Harness 窗口点同意 / 拒绝」，
并且**不显示** ✓/✗ 面板（那种情况下按钮送不出去，显示出来只会误导）。
`pendingApprovals[].answerable = false` 时同样收起面板。

### 为什么插件端点是审批的唯一来源

权限审批不进会话投影缓存。唯一来源是插件的 `/kun-pet/state`。
**插件没被加载时该端点直接 404**，`pendingApprovals` 永远是空的 ⇒ 桌宠不可能提示审批。
所以「审批气泡弹不出来」的第一排查对象永远是「插件挂上了没有」。

### 两个静默失败（已补）

1. 路由注册改成 `ctx.inject(['webServer'], …)`：不再假设 `apply` 一定跑在 webServer 就绪之后；
2. 插件自己的日志 `~/.dsh/kun-pet-host.log`：挂载、HTTP 通道就绪、注册异常、卸载都会写一行（带 `[pid N]`）。
   启动后还会写一行能力探测：`capability probe: GUI approval card cancel = available|UNAVAILABLE`。

### 桌宠批了之后网页卡片还挂着（已修）

审批有**两个应答者**：

- DSH 的远程转发（`@deepseek-ai/dsh-api-remotes`）把 `approval/request` 转发给网页端；
  网页端那张卡只有在收到 Gateway 的 `{type:'cancel', eventId}` 帧时才会被撤下；
- 桌宠这个应答者**在瀑布上游**，它先返回结果时下游转发链只是被丢下，Gateway 并不知道请求已结束 ⇒ 卡片一直挂着。

修法（`cancelGuiApprovalCard`）：桌宠按钮答的请求，顺手把对应的 pending 远程事件 `cancelRemoteEvent` 掉，
网页端立刻撤卡；网页端自己先答的**不会**多此一举。
取不到 Gateway 内部结构时（换 DSH 版本、接口变动）不崩，只记一行日志，并自动退回**兜底策略**：
先给桌宠一个独占窗口（`approvalWindowMs`，默认 6 秒），窗口内没人答才把请求交给网页端。

## 8. 位置与配置的持久化

`kun-pet-settings.json` 与日志**固定在脚本所在目录**，而不是当前工作目录。
原因：`ScriptBlock::Create` 执行脚本时 `$PSScriptRoot` 为空，所以三个启动器都显式把
「脚本所在目录」作为 `$cwd` 传进来。否则「双击启动」和「开机自启」会各自读写不同的配置文件，
表现就是「换个方式启动就恢复不出上次的形象」。

`petId` 的兜底规则：

| `petId` | 含义 | 启动时 |
|---|---|---|
| 素材目录名（如 `ikkun`） | 上次选的是这个素材 | 直接恢复 |
| `builtin` | 上次**主动选了**「内置形象」 | 恢复内置形象（**不会**被素材顶替） |
| `none` / 字段不存在 | 从没选过（首次运行） | 自动挑第一个可用素材；没有素材才用内置形象 |

素材被卸载 / 改名 / WebP 解码失败时：自动换用另一个可用素材（不掉回默认形象），
并**保留原 `petId` 不覆盖**，等素材装回来下次启动仍会恢复它。菜单里勾选的永远是**当前真正在显示**的那一项。

## 9. 素材格式

```
~/.petdex/pets/<slug>/pet.json
~/.petdex/pets/<slug>/spritesheet.png | spritesheet.webp
```

- 默认 **8 列 × 9 行**，每格 **192×208**（也兼容 8×11）；
- 行顺序 = 9 个动作顺序：`idle / running-right / running-left / waving / jumping / failed / waiting / running / review`；
- `pet.json` 里可以用 `columns` / `rows` / `frameWidth` / `frameHeight`（也接受 `cols` / `cellWidth` 等别名）覆盖默认值；
- ⚠️ **WPF 原生不支持 WebP**。只有 `.webp` 时需转 `.png` 或装 Windows「Webp 图像扩展」；
  菜单里会标注「需 WebP 扩展」表示当前无法解码。本仓库自带素材同时提供 `.png` 与 `.webp`。

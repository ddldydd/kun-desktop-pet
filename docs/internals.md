# 实现说明（原理与设计取舍）

本文写给想看源码 / 想改的人。只想知道怎么用的话，看 [README](../README.md) 就够了。

---

## 1. 总体结构

```
desktop/kun-pet-desktop.ps1     单文件应用：WPF 渲染 + 状态机 + 素材加载 + 托盘 + 审批面板
plugin/index.js                 DSH 插件 host 半区：状态机、HTTP/文件双通道、审批应答
plugin/client.js                DSH 插件 client 半区：Harness 网页右下角那只小宠
install.ps1 / uninstall.ps1     安装 / 卸载
tools/autostart/                开机自启模板（纯 ASCII）
```

桌宠**不依赖插件也能跑**：拿不到任务状态时就停在待机动画。插件是「任务进展 + 审批」的数据来源。

---

## 2. 状态从哪来（三级降级）

| 优先级 | 来源 | 能得到什么 |
|---|---|---|
| 1 | 插件 HTTP `/kun-pet/state` | 当前模式、正在执行的工具名、**待审批列表** |
| 2 | 会话投影缓存 `~/.dsh/storages/session_projcache/sessions/*.json` | 是否在跑、跑了几轮几步、**是否在等你回答**、当前任务内容、模型/工具耗时 |
| 3 | `~/.dsh/sessions` 文件写入时间 | 粗略活跃度（兜底） |

底部小字会显示当前实际生效的来源。

### 为什么优先读会话投影缓存

审批**不在**会话投影里，但「在跑 / 轮次 / 任务内容 / 是否在等你回答」都在，而且是**明文 JSON、始终可用**（不需要插件挂上、不需要知道端口）。所以桌宠的默认数据源是它，插件的 HTTP 端点作为**增强**（补「正在执行哪个工具」和审批）。

### 只跟随主会话

子代理（subagent）会话也有同样的缓存文件，而且干活时更新更频繁。桌宠通过
`record.rows.subagent.val.identity.mode` 是否存在来识别子代理并跳过，避免把子代理的状态显示成你的主任务。

### 多会话聚合

桌宠是**全局**的：扫描全部活跃主会话，逐会话跟踪「上一帧是否在跑」，聚合出全局模式与逐任务进展。
旧实现只取「最近写入的一个会话」，于是别的会话就算还在进展也会被忽略（表现为「任务在跑却没有气泡」）。

### 一个容易踩的坑：问题藏在嵌套里

会话投影里，Agent 的提问挂在 `userQuestions.val.questions.active[]` 的**嵌套 `questions[]`** 里
（字段：`id / question / detail / header / options[{label,description}] / multiSelect / intent`）。
早期代码直接读条目本身的 `question`，于是永远只显示一句「Agent 正在等待你的回答」。

另一个坑：`active` 条目的 `state` 为 `continued` 时表示**已经答过、Agent 正在继续**，
只认 `state = open` 才是真的在等你。

## 3. 频闪是怎么修的（v2 的两个根因）

现象：小宠每隔约 1 秒「消失一瞬」再出现。

**根因 1：素材每行末尾有空帧。**
petdex / Codex 的精灵图统一是 8 列，但每个动作真正有内容的帧数不同。实测：

| 形象 | idle | running-right | running-left | waving | jumping | failed | waiting | running | review |
|---|---|---|---|---|---|---|---|---|---|
| ikkun | 6 | 8 | 8 | 4 | 5 | 8 | 6 | 6 | 6 |
| haiyue-classic | 6 | 8 | 8 | 4 | 5 | 8 | 6 | 6 | 6 |

固定按 8 列循环时，走到空格子小宠就「不见了」。
现在**启动时逐行扫描素材**（`KunPet.SpriteScan.UsableCols`，读 BGRA 的 alpha 通道，隔行隔列采样），
只在该行真正有内容的列之间循环，并把 `frames/row: 6,8,8,4,5,8,6,6,6` 写进日志。

**根因 2：逐帧亚像素缩放/位移。**
整只小宠每帧被 ±2% 地重新缩放并做小数位移，像素贴图每帧重新采样，边缘来回抖。
现在**素材形态下缩放固定、位移取整**（提醒时的脉冲改成整像素弹跳），每帧栅格完全一致 ⇒ 画面是稳的
（连续帧可以完全一模一样）。内置矢量形象是纯路径、缩放不重采样，所以保留原来的呼吸 / 脉冲效果。

顺带修掉的三个问题：

- **气泡一窄小宠被裁**：窗口是 `SizeToContent`，气泡宽度会改变窗口宽度，而贴图比容器大、不参与布局，
  于是气泡窄时小宠左右被裁。现在容器尺寸跟着素材格走，整张贴图都计入布局。
- **气泡换行时小宠上下跳**：窗口从左上角扩展，气泡多一行小宠就下移一截。现在尺寸变化时钉住
  「**底边 + 水平中心**」：气泡向上生长，小宠待在原地；存盘也一并存窗口尺寸，重启后按底边+中心还原（并夹在工作区内）。
- **启动时处于暂停会显示 `...`**：现在暂停（菜单切换或带 `paused` 启动）也会按当前状态渲染一次气泡与底部提示。

自查工具：

- `docs/tools/check-sheet-frames.py` —— 打印每只宠物每行的有效帧数（找出空帧）
- 想验「画面不闪」：连续截图比对小宠区域像素数是否稳定

## 4. 暂停的语义

菜单里的「暂停」**只冻结小宠本身**：不推进动画帧、不浮动 / 缩放、点击不再挥手出声。
**任务气泡、进度、底部提示、提醒全部照常更新**——暂停动画也不会漏掉任务进展。

实现上：500 ms 轮询照常跑、状态该切就切；动画定时器在暂停时仍然刷新气泡文字 / 进度 / 等待提示，
只是不重画小宠；提示音、托盘通知、置顶抢焦点同样有效。

## 5. 审批通道（插件的核心）

### 两条通道

| 通道 | 位置 | 能力 |
|---|---|---|
| HTTP | `/kun-pet/state`、`/kun-pet/approval` | 读状态 + **在桌宠上直接 ✓同意 / ✗拒绝** |
| 文件 | `~/.dsh/kun-pet-state.json`（内容与 HTTP 响应体一致） | 读状态（气泡照常提示，决策要回 Harness 点） |

桌宠优先 HTTP，失败自动退回文件。只有文件通道时，气泡会提示「切回 Harness 窗口点同意 / 拒绝」，
并且**不显示** ✓/✗ 面板（那种情况下按钮送不出去，显示出来只会误导）。
`pendingApprovals[].answerable = false` 时同样收起面板。

### 为什么插件端点是审批的唯一来源

权限审批不进会话投影缓存。唯一来源是插件的 `/kun-pet/state`。
**插件没被加载时该端点直接 404**，`pendingApprovals` 永远是空的 ⇒ 桌宠不可能提示审批。
所以「审批气泡弹不出来」的第一排查对象永远是「插件挂上了没有」。

### 两个静默失败（已补）

1. 路由注册改成 `ctx.inject(['webServer'], …)`：不再假设 `apply` 一定跑在 webServer 就绪之后；
2. 插件自己的日志 `~/.dsh/kun-pet-host.log`：挂载、HTTP 通道就绪、注册异常、卸载都会写一行（带 `[pid N]`）。
   启动后还会写一行能力探测：`capability probe: GUI approval card cancel = available|UNAVAILABLE`。

### 桌宠批了之后网页卡片还挂着（已修）

审批有**两个应答者**：

- Harness 的远程转发（`@deepseek-ai/dsh-api-remotes`）把 `approval/request` 转发给网页端；
  网页端那张卡只有在收到 Gateway 的 `{type:'cancel', eventId}` 帧时才会被撤下；
- 桌宠这个应答者**在瀑布上游**，它先返回结果时下游转发链只是被丢下，Gateway 并不知道请求已结束 ⇒ 卡片一直挂着。

修法（`cancelGuiApprovalCard`）：桌宠按钮答的请求，顺手把对应的 pending 远程事件 `cancelRemoteEvent` 掉，
网页端立刻撤卡；网页端自己先答的**不会**多此一举。
取不到 Gateway 内部结构时（换 DSH 版本、接口变动）不崩，只记一行日志，并自动退回**兜底策略**：
先给桌宠一个独占窗口（`approvalWindowMs`，默认 6 秒），窗口内没人答才把请求交给网页端。

## 6. 位置与配置的持久化

`kun-pet-settings.json` 与日志**固定在脚本所在目录**，而不是当前工作目录。
原因：`ScriptBlock::Create` 执行脚本时 `$PSScriptRoot` 为空，所以三个启动器都显式把
「脚本所在目录」作为 `$cwd` 传进来。否则「双击启动」和「开机自启」会各自读写不同的配置文件，
表现就是「换个方式启动就恢复不出上次的形象」。

`petId` 的兜底规则：

| `petId` | 含义 | 启动时 |
|---|---|---|
| 素材目录名（如 `ikkun`） | 上次选的是这个素材 | 直接恢复 |
| `builtin` | 上次**主动选了**「内置形象」 | 恢复内置形象（**不会**被素材顶替） |
| `none` / 字段不存在 | 从没选过（首次运行） | 自动挑第一个可用素材；没有素材才用内置形象 |

素材被卸载 / 改名 / WebP 解码失败时：自动换用另一个可用素材（不掉回默认形象），
并**保留原 `petId` 不覆盖**，等素材装回来下次启动仍会恢复它。菜单里勾选的永远是**当前真正在显示**的那一项。

## 7. 素材格式

```
~/.petdex/pets/<slug>/pet.json
~/.petdex/pets/<slug>/spritesheet.png | spritesheet.webp
```

- 默认 **8 列 × 9 行**，每格 **192×208**（也兼容 8×11）；
- 行顺序 = 9 个动作顺序：`idle / running-right / running-left / waving / jumping / failed / waiting / running / review`；
- `pet.json` 里可以用 `columns` / `rows` / `frameWidth` / `frameHeight`（也接受 `cols` / `cellWidth` 等别名）覆盖默认值；
- ⚠️ **WPF 原生不支持 WebP**。只有 `.webp` 时需转 `.png` 或装 Windows「Webp 图像扩展」；
  菜单里会标注「需 WebP 扩展」表示当前无法解码。本仓库自带素材同时提供 `.png` 与 `.webp`。
